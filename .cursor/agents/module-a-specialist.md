## TDD iron law

```
NO PRODUCTION CODE IN src/ WITHOUT A FAILING TEST FIRST.
Write test → watch it fail → implement minimal code → watch it pass → refactor.
Rationalization is violation. Delete pre-written code. Start over.
```

## Phase 1 — Preflight (before any code change)

1. **Data quality audit** — run DAMA-5 scorecard on any input dataset being touched:

   | Dimension | Minimum threshold | Block condition |
   |-----------|------------------|----------------|
   | Completeness | `municipality` null rate < 8% pre-clean; < 0.1% post-clean | Pipeline must not proceed on failed QA gate |
   | Consistency | Duplicate `cedula` rate within expected 0.5–2% range | > 2% triggers config review |
   | Validity | Zero `age_on_event_date` < 18 or > 115 in clean layer | Any violation = `QAGateFailure` |
   | Timeliness | `generation.yaml:sample_size` documented; full-scale run path in `config/full_scale_run.md` | Missing = incomplete deliverable |
   | Uniqueness | `entity_id` unique and monotonic | Any duplicate = `QAGateFailure` |

2. **Calibration anchor check** — every TSJE/DGEEC anchor must be within tolerance before proceeding to modeling:

   | Anchor | Value | Tolerance |
   |--------|-------|-----------|
   | National participation rate | 61.25% | ±0.1 pp |
   | Youth cohort (18–24) participation | 52.8% | ±0.5 pp |
   | Female participation | 69.46% | ±0.2 pp |
   | Male participation | 67.72% | ±0.2 pp |
   | Alto Paraná participation | 37.47% | ±0.5 pp |
   | Guairá participation | 58.26% | ±0.5 pp |
   | Urban share | 61.7% | ±0.3 pp |
   | Jopará bilingual share | 46% | ±1 pp |

3. **Terminology scan** — no banned terms (scope §12) in field names, strings, or comments that will ship.

## Phase 2 — Implement (test-first)

For each logical unit of behavior:
1. Write the failing test (`pytest tests/module_a/.../test_<what>.py`).
2. Run test — **must fail** for the expected reason (feature missing, not syntax error).
3. Write minimal implementation.
4. Run test — must pass. All existing tests must stay green.
5. Refactor only after green.

**No behavior change in `src/` without this cycle. No exceptions.**

For bugs: follow systematic-debugging four phases. **No fix without root cause. No fix without failing test reproducing the bug first.**

## Phase 3 — Validate (quantitative thresholds)

Run the full Module A quality gate checklist before claiming done:

| Gate | Pass condition |
|------|----------------|
| A1 | All calibration anchors in `calibration_anchors.yaml` pass tolerance in `validator.py` |
| A2 | All 13 flaw types present in `population_master_raw.parquet` within ±20% of configured injection rates |
| A3 | Municipality null rate: 8% pre → < 0.1% post; duplicate collapse count > 0; zero garbled chars in clean layer |
| A4 | DBSCAN noise flag rate < 1% (> 3% = config review + decision log entry) |
| A5 | Mean silhouette score k=6 > 0.35 on test partition |
| A6 | Mean ARI across 100 bootstrap resamples > 0.80 |
| A7 | Brier score on test partition < 0.22 (beats naive 0.238 baseline) |
| A8 | Youth cohort mean propensity within ±0.5 pp of 52.8% |
| A9 | Female mean propensity within ±0.2 pp of 69.46%; male within ±0.2 pp of 67.72% |
| A10 | All four TSJE exemplar departments within ±0.5 pp of anchors |
| A11 | All 6 segments contain ≥ 1% of total population |
| A12 | Streamlit dashboard loads; all three tabs render; k-slider updates without refresh error |

**BLOCK:** Do not proceed to Phase 4 if any gate fails. Fix first, then re-run gate.

## Phase 4 — Publish evidence

Before running `/task-verify`, produce:
1. **QA report** at `reports/qa_report_YYYYMMDD.md` (auto-generated by pipeline; verify it exists and all PASS/FAIL rows pass).
2. **Test output** — paste or link exact pytest output with pass count.
3. **Gate mapping** — for each A1–A12 gate above, state `PASS` with evidence or `FAIL` with action.
4. **Model card update** — if a model changed, confirm `model_card_segmentation.md` or `model_card_propensity.md` reflects the change.
5. **Transformation log entry** — if a cleaning step changed, add entry to `reports/transformation_log.md`.
