# Development process

How this repository was built.

## Workflow

A controlled, AI-assisted loop was used throughout:

1. **Plan-first.** Every non-trivial change begins with a written task brief: goal, acceptance criteria, files touched, expected risk surface. Plans live in `project_scope/` and `maintainer/` (internal).
2. **Execute.** Code, tests, schemas, and docs are produced together. Tests precede or accompany implementation. Schema contracts (Pandera) are enforced at module boundaries.
3. **Verify.** Each unit closes only after `make validate` (lint + typecheck + tests + coverage), schema round-trip, and—where applicable—DVC pipeline reproduction with hash comparison.
4. **Document.** Decisions land in `reports/decision_log.md`; epistemic boundaries (verified vs calibrated vs simulated vs illustrative) are tracked per artifact in `reports/epistemic_boundaries.md`.

## AI as pair-programmer

Claude (Anthropic) and Cursor were used to draft code, write tests, refactor, and accelerate documentation. The author reviewed and accepted every commit before merge; no code is committed that was not read, understood, and validated against the project's quality gates.

This matches the 2026 baseline for solo applied decision-analytics work: human owns the architecture, requirements, mathematical formulation, and acceptance criteria; AI accelerates the mechanical surface (test fixtures, boilerplate, parallel doc writing, idiomatic refactoring).

## What the reader is evaluating

- The **engineering discipline**: schema contracts, CI gates, type-checked code, reproducibility manifests, decision logs.
- The **statistical rigor**: walk-forward validation, MCMC diagnostics (R̂, ESS, divergences), bootstrap stability, calibration metrics with explicit caveats.
- The **epistemic honesty**: the four-tier verified/calibrated/simulated/illustrative taxonomy applied per artifact, including explicit limitations on synthetic-target metrics.
- The **systems thinking**: how the three modules compose (population → allocation → tracking) and where the boundaries are.

Not the typing-ratio between human and assistant.

## Repository conventions

- Branch-per-task; PR titles encode the unit.
- Commit messages mention `Co-Authored-By` where AI assistance was direct.
- All test counts and coverage figures derive from `docs/test_inventory.md` (regenerated by `make test-inventory`).
- Module-level READMEs link to deeper specifications; the top-level README is the entry surface.
